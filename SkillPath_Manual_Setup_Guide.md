# SkillPath — Manual Setup Guide

This document contains the manual steps required before running the SkillPath project.

> **Important:** Never commit API keys, LiveKit API secrets, Supabase service-role keys, or other secrets to GitHub.

---

## 1. Prerequisites

Install:

- Flutter SDK
- Android Studio
- Android SDK
- Git
- Python 3.11+ (for the LiveKit Agent)
- Node.js (if using the React/Next.js admin)
- VS Code or Android Studio

Verify Flutter:

```bash
flutter doctor
```

Verify Git:

```bash
git --version
```

Verify Python:

```bash
python --version
```

---

# 2. Create the Project

Create the Flutter application:

```bash
flutter create skillpath
cd skillpath
```

If using the recommended repository layout:

```text
skillpath/
├── mobile/
├── admin/
├── agent/

```

You can create the Flutter app inside `mobile`:

```bash
flutter create mobile
```

---

# 3. Create a Supabase Project

Open the Supabase dashboard:

https://supabase.com/dashboard

1. Sign in.
2. Create a new project.
3. Choose an organization.
4. Enter a project name, for example:

```text
skillpath
```

5. Set a strong database password.
6. Select a suitable region.
7. Wait for the project to finish provisioning.

---

# 4. Get Supabase URL and Publishable Key

Open your Supabase project.

Go to the project's **Connect** section/API settings.

Copy:

```text
Project URL
Publishable key
```

Use the publishable/anon client key in the Flutter app.

Do NOT put the Supabase service-role key in Flutter.

Supabase's Flutter documentation uses the project URL and publishable key for client initialization.

Example:

```dart
await Supabase.initialize(
  url: 'YOUR_SUPABASE_URL',
  publishableKey: 'YOUR_SUPABASE_PUBLISHABLE_KEY',
);
```

Reference:

https://supabase.com/docs/guides/getting-started/quickstarts/flutter

---

# 5. Add Supabase to Flutter

From the Flutter project:

```bash
flutter pub add supabase_flutter
```

Then initialize Supabase in the application startup.

Use build-time configuration or another secure configuration mechanism instead of committing secrets directly into source code.

# 9. Get a Gemini API Key

Google AI Studio is the easiest route for Gemini API development.

Open:

https://aistudio.google.com/

1. Sign in with your Google account.
2. Open the API key section.
3. Create an API key.
4. Copy the key.
5. Keep it private.

Google's current Gemini API documentation says Google AI Studio can create a project/API key for new users and provides a Create API key flow.

Official documentation:

https://ai.google.dev/gemini-api/docs/get-started

For the LiveKit Gemini plugin, the backend environment variable is:

```text
GOOGLE_API_KEY=your_key_here
```

Never put this key in Flutter.

---

# 10. Gemini API Billing / Quotas

Gemini has free-tier availability for eligible models and usage, but quotas and model availability can change.

For a hackathon:

- monitor usage
- keep conversations short during testing
- avoid unnecessary repeated requests
- check the Google AI Studio usage dashboard

Do not assume unlimited free usage.

If Google requires billing for the model/API configuration you select, follow the current Google billing instructions.

---

# 11. Create a LiveKit Cloud Account

Open:

https://cloud.livekit.io/

1. Create/sign in to your LiveKit account.
2. Create a project.
3. Give it a name:

```text
SkillPath
```

4. Open the project settings.
5. Obtain the project URL/API credentials required by the backend.

You will need:

```text
LIVEKIT_URL
LIVEKIT_API_KEY
LIVEKIT_API_SECRET
```

The API secret must remain server-side.

# 12. Install LiveKit CLI

On Windows, the official LiveKit documentation provides a Windows installation option.

One available method is:

```powershell
winget install LiveKit.LiveKitCLI
```

Then authenticate:

```bash

```

This connects the CLI to your LiveKit Cloud account.

Verify:

```bash

```

Official documentation:

https://docs.livekit.io/reference/developer-tools/livekit-cli/projects/

# 13. Configure LiveKit Agent

The recommended architecture is:

Flutter
→ LiveKit
→ SkillPath Agent
→ Gemini Live
→ Supabase

Create:

```text
agent/
├── main.py
├── tools/
├── prompts/
├── services/
├── requirements.txt
└── .env
```

Install the required LiveKit/Gemini agent packages according to the current LiveKit documentation.

For Python, LiveKit's current Gemini plugin documentation uses the Google plugin with LiveKit Agents.

Example package:

```bash
uv add "livekit-agents[google]~=1.8"
```

If the coding agent chooses a newer compatible version, use the current version documented by LiveKit rather than forcing an obsolete version.

Official Gemini Live + LiveKit documentation:

https://docs.livekit.io/agents/models/realtime/plugins/gemini/

# 17. LiveKit Token Generation

Flutter must NOT generate LiveKit tokens using the API secret.

Use a secure backend endpoint/Edge Function.

Flow:

```text
Flutter
  ↓
authenticated request
  ↓
backend token endpoint
  ↓
LiveKit access token
  ↓
Flutter joins room
```

Token should be short-lived.

Do not expose:

```text
LIVEKIT_API_SECRET
```

to the mobile application.

# 33. Troubleshooting

## Gemini key not working

Check:

- API key is correct
- selected model is available to your account
- quota is not exhausted
- backend environment variable is loaded

Never put the Gemini key directly into Flutter.

---

## LiveKit connection fails

Check:

```text
LIVEKIT_URL
LIVEKIT_API_KEY
LIVEKIT_API_SECRET
```

Check that the token is generated by the backend.

Check microphone permissions.

Check the agent is running/deployed.

---

## AI connects but does not answer

Check:

- Gemini API key
- selected realtime model
- LiveKit agent logs
- microphone audio publication
- agent joined the same room
- current LiveKit/Gemini plugin versions

---

## AI invents salary

This is a serious bug.

Verify that:

1. The tool is being called.
2. Tool results contain verified data.
3. The system prompt prohibits unsupported claims.
4. The agent does not answer factual outcome questions without retrieval.
5. Missing data produces an explicit "data unavailable" response.

---

## Supabase permission denied

Check:

- RLS is enabled
- policies are correct
- authenticated role has required access
- Data API exposes the necessary tables/functions
- service-role key is only used server-side

---
